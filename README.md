# Mandelbrot Canvas

一个只有全屏 Canvas 的单页静态站点，使用 TypeScript 和 Vite，没有前端框架或服务端依赖。

## 本地运行

```sh
npm install
npm run dev
```

## VS Code 启动

安装依赖后，用 VS Code 打开项目根目录，选择「dev」配置并按 F5，即可在终端启动 `npm run dev`。浏览器由你自行打开，访问终端显示的地址（当前为 `http://127.0.0.1:59472/`）。

开发端口使用 `package.json` 中的配置。启动前，请先停止手动运行的同项目开发服务器，避免端口冲突。

## 构建与预览

```sh
npm run build
npm run preview
```

将 `dist/` 目录部署到静态托管服务即可。

## 操作

- 鼠标滚轮：以指针位置为不动点缩放；滚轮事件发生在画布外时，以画布中心为不动点。
- 鼠标左键拖拽或触屏单指拖动：平移视口，拖出画布后仍保持捕获。
- 触屏双指：同时支持缩放与平移；增加、抬起或取消触点时重新计算手势基准，避免跳动。
- 右下角「重置」按钮或 `Home`：恢复集合全貌。重置按钮只在视图偏离默认视图（缩放或平移）后显示，处于默认视图时隐藏；`Home` 始终可用。
- 左下角横向显示画布中心的复数坐标（Re 实部、Im 虚部）及相对于当前窗口初始视图的放大倍率，右下角单独保留重置按钮。屏幕宽度不超过 640px 时，坐标栏占满底部宽度，重置按钮移到坐标栏上方并保持靠右。放大倍率始终完整显示，坐标在剩余宽度内缩略。较长坐标根据可用宽度在中间显示省略号，保留首尾数字；点击坐标（或键盘聚焦后按 Enter / 空格）可查看完整值。详情浮层会自动换行，支持滚动和选择复制，点击「关闭」或按 Esc 返回。极大倍率使用科学计数法。
- 坐标栏末尾的复制按钮始终复制完整的中心实部、虚部和放大倍率，不包含省略号；复制后显示结果提示。

窗口大小或屏幕像素密度变化时保持当前复平面中心与缩放尺度，重新绘制。初始视图及 Home 重置会完整显示集合。Canvas 使用屏幕完整的 `devicePixelRatio`（包括 3 倍及更高密度），静止画面按物理像素 1:1 绘制。交互期间显示即时变换的预览，后台逐步补齐原生分辨率；像素越多，完整细节的计算时间和内存占用也越高。

## 深度缩放与性能

本项目面向支持原生 BigInt、模块 Worker、Pointer Events 的现代浏览器，所有计算均在本机完成。

1. `src/precision.ts` 使用 BigInt 二进制定点数保存复平面中心，精度随缩放深度按 64 位递增，并保留超过一个屏幕像素所需精度的至少 128 个保护位。尺度保存为二进制对数；既不把整个高精度坐标转换成普通浮点数，也不把极小尺度直接保存为 `number`。
2. 浅层使用普通双精度迭代，每次交错推进同一行的三个像素：单条轨道的每次迭代都要等待上一次的结果，交错独立轨道能让浮点单元保持忙碌，速度约为逐像素的 2 倍，每条轨道的运算与逐像素版本完全相同，结果逐位一致。轨道状态完全重复时提前判定为不逃逸。
   内部像素不会逃逸，若没有捷径，就会把整个迭代预算跑满。轨道接近此前的近零点后，用后续一个候选周期验证一个圆盘：按 `|f(w) − f(z)| ≤ r(2|z| + r)` 并计入每一步的舍入误差界，同时尝试四种初始半径，若 P 步后圆盘的像落回圆盘内，则 `f^P` 把它映入自身，轨道永不逃逸，像素即判定为内部。这是区间式的包含证明，不是近似阈值：它只会提前给出本来就会到达的“未逃逸”结论，逃逸像素的结果不受影响。尝试次数和步数都有上限，不会让单个像素的工作量超过一倍；超深层的扩展指数路径用以 2 为底的对数跟踪半径。
   深层在 Worker 中计算一条高精度参考轨道，像素通过扰动递推 `δz′ = 2Zδz + δz² + δc` 复用它。参考轨道可在允许的范围内跨平移、缩放复用；参考点距视图中心超过 2^24 个 CSS 像素时会重新计算，避免缩小后再偏离中心深入放大时，像素差异被浮点精度吞没。
   高精度轨道只由 0 号 Worker 计算一次；每次迭代复用新值的平方同时完成逃逸判断和下一步，只需 3 次大整数乘法（原为 5 次），定点转浮点时先移位到约 64 位再求位长，不再把数千位的值转成二进制字符串，结果逐位相同，极深层的参考轨道快约 2.3 倍。轨道以紧凑的类型数组经主线程转发给其余 Worker，各自据此构建 BLA 表，结果与本地计算逐位一致。正在计算的轨道若仍被新请求需要会继续进行，不会因连续缩放反复重启。
3. 极深层的扰动使用独立的二进制指数，避免在约 `10^-308` 处下溢。满足保守误差半径时，BLA（双变量线性近似）跳过连续迭代；单步略去 `|δ|²` 的条件为 `|δ| < 2^-36 |2Z|`，等效于把采样点移动约 10^-8 像素，远小于边界附近精确逃逸次数在 10^-3 像素内本身的变化，跳过的迭代比 2^-42 多至数倍。普通深度的 BLA 表以每层一个 `Float64Array` 存储，内存约为对象形式的四分之一；每个位置先用第 0 层半径快速排除（更长的块半径不会更大），省去大多数查表；抵消阈值按轨道位置预先计算，参考值和 `|δ|²` 跨步复用，内部证明的跟踪先用保守的远离阈值排除，单步扰动的结果逐位不变。检测到严重抵消时回退到该像素的 BigInt 直接迭代；需要时重新对齐参考轨道。
   普通指数范围内的扰动使用平方模检查逃逸、抵消和 BLA 半径，避免在每一步重复调用模长和对数运算；平方可能下溢时回到稳定的模长比较，极深层仍使用扩展指数路径。
4. 主线程用 `requestAnimationFrame` 变换已有图像，立即响应手势；Worker 按需创建并复用，最多 8 个，通常为页面保留一个逻辑核心。根据待补算像素数、缩放深度和参考轨道的估算内存选择活动线程数，小区域会减少线程，极长参考轨道也会限制并发。先输出低分辨率预览，再按 8、4、2、1 像素步长补全细节。每一步最终都会到达实际画布分辨率。
   每个 Worker 在四个阶段中负责固定的空间分块。粗阶段在每个块的左上像素中心采样，因此每个粗采样都恰好是一个最终像素；更细的阶段直接沿用这四分之一的结果而不重算。最终图像与逐像素计算完全相同，总计算量减少约 25%。粗采样以采样像素为中心绘制（相邻分块的绘制范围恰好拼接，区域边缘由最后一列/行补齐），各阶段预览与最终图像的位置偏差不超过半个物理像素，细化时画面不会来回移动。
   缩放后新渲染的预览是旧图像的投影：放大 F 倍时，已完成到步长 s 的旧图相当于间距 F·s 的采样。比这更粗的阶段仍会计算（统计用于迭代预算），但不再覆盖这块更清晰的预览，否则颗粒会先变大再变小，看起来在清晰与模糊之间来回切换；最终阶段总会绘制。
   浅层每秒可完成上万个分块。Worker 约每 16 ms 批量发送一次，主线程把分块写入 CPU 暂存缓冲，每帧只向画布上传一次，避免大量小块上传阻塞手势和绘制。分块尚未被更细结果占用时整块认领，粗块按行展开后用 `copyWithin` 复制相同的行，主线程处理一次全图约 33 ms（原约 55 ms）。
   同倍率平移会复用重叠区域已完成的高清像素，只计算新露出的区域及尚未完成的部分。像素与完成状态一起按物理像素移动，避免反复插值造成模糊；不足一物理像素的位移保留在高精度视图坐标中累积，显示与坐标之间最多相差半个物理像素。缩放、窗口尺寸或屏幕像素密度变化，以及平移超过缓存范围时，重新计算全图。缓存限于当前画布，不会随探索距离无限增长。
5. 新请求会协作取消旧计算：Worker 每计算约 8 ms 让出一次以处理新消息，用自发的 `MessageChannel` 消息而非 `setTimeout(0)`（后者嵌套后被浏览器限制为至少 4 ms，会让 Worker 空等约三分之一的时间）；结果携带任务编号，旧结果不能覆盖新视口。分块质量记录阻止迟到的低分辨率结果覆盖已完成的高分辨率像素。
6. 迭代预算随深度增长，并按实际情况自适应：粗阶段有超过 1% 的采样在预算内既未逃逸也未被证明为内部时，预算提高到 4 倍并重新绘制（颜色只取决于逃逸次数，已逃逸的像素不变）。提高不再明显减少未定像素时停止，上限为深度公式的 64 倍（2^16 到 2^20 之间）；学到的预算在附近继续沿用，缩小 8 个二进制量级以上或按 Home 后恢复公式。例如海马谷约 10^15 倍处，按公式的 2560 次迭代整幅画面都是黑色，实际像素需要数千到数万次迭代。
   源码没有固定的放大倍数上限，但真实计算仍受 CPU、内存、迭代预算与数值误差影响；不能保证任意区域、任意深度都实时完成高清重绘。黑色表示已被证明不会逃逸，或在当前（自适应）预算内未逃逸；后者并非严格的集合归属证明。极深缩放时，先显示可即时操作的缓存画面，再渐进生成新细节。

配色参考 `Mandelbrot_sequence_new.gif` 的 475 帧颜色统计，以及[原图说明](https://commons.wikimedia.org/wiki/File:Mandelbrot_sequence_new.gif)链接的[黄金渐变色值](https://github.com/josch/mandelbrot_zomb/blob/master/src/deepZoom/MandelAnimator.java)。从宝蓝、浅青、近白过渡到金黄、赭红、深蓝紫，集合内部保持黑色。色带宽度不均匀，以周期性单调三次插值生成 4096 段查询表，避免直线渐变的生硬连接和偏灰过渡；着色时查 4 倍分辨率的打包 RGBA 表，每个像素一次查表、一次精确取模，比逐通道插值快约一倍，与插值结果最多相差 1 个色阶。

色盘形状与循环频率分别控制：前 144 次平滑迭代保留参考图的平方根相位；144–512 次之间平滑提高循环频率，超过 512 次后固定每 128 次迭代循环。这样既保留浅层观感，又避免深层周期越拉越长、局部迭代差异落在同一片颜色中。过渡两端的相位与一阶导数连续。映射始终只依赖逃逸次数，不随窗口、平移或迭代预算变化，已有像素缓存仍可复用。这是参考配色的视觉拟合，并非原动画算法的逐像素复刻；原 GIF 还使用多重采样，本次未增加实时渲染的采样数量。

配色位于 `src/palette.ts`，迭代预算和扰动算法位于 `src/fractal.ts`，指数扩展运算位于 `src/extended.ts`，手势和渲染调度位于 `src/main.ts`，页面样式位于 `src/style.css`。

算法依据：[Claude Heiland-Allen 的 Deep Zoom](https://mathr.co.uk/web/deep-zoom.html) 及 [Deep zoom theory and practice](https://mathr.co.uk/blog/2021-05-14_deep_zoom_theory_and_practice.html)。本项目为 TypeScript 实现，没有引入分形运行时依赖。

## 验证

使用 Node.js 22.18+（建议 24+）执行：

```sh
npm test
npm run build
```

测试覆盖鼠标锚点、画布外中心缩放、连续 3000 次缩放、深层拖拽、双指缩放和平移、触点取消、任务取消、渐进像素覆盖及乱序结果保护。数值测试用额外增加 64 位精度的直接 BigInt 迭代作对照，覆盖非实轴复杂边界和每像素 `2^-2000`（约 `10^-602`）的尺度；混沌边界区域按 10^-3 像素位移内的精确值变化范围比较。另有测试检查三路交错与逐像素结果逐位一致、内部证明在 4 倍 BigInt 预算下无一逃逸、超深层迷你集内部被快速证明、粗采样复用后的深层图像与逐像素采样相同，以及预算自适应的提高、停止与遗忘；这验证了这些测试点，不代表对所有深度和边界的数学正确性证明。

## 性能基准

```sh
npm run bench
npm run bench:workers
# 可单独指定线程数（1–8）
npm run bench:workers -- 2 4 8
```

`bench` 对固定的五个视图采样 160×100 个像素，预热后报告三轮中位数、参考轨道准备耗时和像素校验和；可传入另一份 `src` 目录比较计算实现。`bench:workers` 使用实际 Worker、384×240 像素和完整渐进过程，包含消息传输，但不包含浏览器绘制。

2026-11-06 本机 Apple M1 Max 的一次对比：深层样例（倍率 `1.50×10^47`）单线程采样从约 421ms 降至 82ms，海马谷样例从约 2155ms 降至 411ms；优化后的深层样例从 4 Worker 的约 197ms 降至 8 Worker 的约 113ms。前后采样校验和相同。结果受设备、位置和负载影响，扩展指数路径的收益较小，这些数值不代表所有视图的整页渲染速度。
