# Mandelbrot Canvas

一个只有全屏 Canvas 的单页静态站点，使用 TypeScript 和 Vite，没有前端框架或服务端依赖。

## 本地运行

```sh
npm install
npm run dev
```

## VS Code 启动

安装依赖后，用 VS Code 打开项目根目录，选择「dev」配置并按 F5，即可在终端启动 `npm run dev`。浏览器由你自行打开，访问终端显示的地址（当前为 `http://127.0.0.1:59472/`）。

开发端口使用 `package.json` 中的配置。启动前，请先停止手动运行的同项目开发服务器，避免端口冲突。

## 构建与预览

```sh
npm run build
npm run preview
```

将 `dist/` 目录部署到静态托管服务即可。

## 操作

- 鼠标滚轮：以指针位置为不动点缩放；滚轮事件发生在画布外时，以画布中心为不动点。
- 鼠标左键拖拽或触屏单指拖动：平移视口，拖出画布后仍保持捕获。
- 触屏双指：同时支持缩放与平移；增加、抬起或取消触点时重新计算手势基准，避免跳动。
- 地址栏的 hash 随缩放、平移更新为当前视图（`#re=…&im=…&zoom=…`），可直接复制链接分享；打开带 hash 的链接会还原到相同的中心和放大倍率。坐标保留到超过一个屏幕像素 3 位的十进制位数，任意深度都能精确还原；放大倍率与界面显示一致，相对于打开者窗口的初始视图，因此不同大小的窗口看到相同的取景。更新使用 `replaceState` 并做了防抖，不会在浏览记录里留下每一步；手动修改 hash 或前进、后退也会跳转到对应视图，无效的 hash 会被忽略。
- 右下角「重置」按钮或 `Home`：恢复集合全貌，并清空地址栏的 hash。重置按钮只在视图偏离默认视图（缩放或平移）后显示，处于默认视图时隐藏；`Home` 始终可用。
- 左下角横向显示画布中心的复数坐标（Re 实部、Im 虚部）及相对于当前窗口初始视图的放大倍率，右下角单独保留重置按钮。屏幕宽度不超过 640px 时，坐标栏占满底部宽度，重置按钮移到坐标栏上方并保持靠右。放大倍率始终完整显示，坐标在剩余宽度内缩略。较长坐标根据可用宽度在中间显示省略号，保留首尾数字；点击坐标（或键盘聚焦后按 Enter / 空格）可查看完整值。详情浮层会自动换行，支持滚动和选择复制，点击「关闭」或按 Esc 返回。极大倍率使用科学计数法。
- 坐标栏末尾的复制按钮始终复制完整的中心实部、虚部和放大倍率，不包含省略号；复制后显示结果提示。

窗口大小或屏幕像素密度变化时保持当前复平面中心与缩放尺度，重新绘制。初始视图及 Home 重置会完整显示集合。Canvas 使用屏幕完整的 `devicePixelRatio`（包括 3 倍及更高密度），静止画面按物理像素 1:1 绘制。交互期间显示即时变换的预览，后台逐步补齐原生分辨率；像素越多，完整细节的计算时间和内存占用也越高。

## 深度缩放与性能

本项目面向支持原生 BigInt、模块 Worker、Pointer Events 的现代浏览器，所有计算均在本机完成。

1. `src/precision.ts` 使用 BigInt 二进制定点数保存复平面中心，精度随缩放深度按 64 位递增，并保留超过一个屏幕像素所需精度的至少 128 个保护位。尺度保存为二进制对数；既不把整个高精度坐标转换成普通浮点数，也不把极小尺度直接保存为 `number`。
2. 浅层使用普通双精度迭代，每次交错推进同一行的三个像素：单条轨道的每次迭代都要等待上一次的结果，交错独立轨道能让浮点单元保持忙碌，速度约为逐像素的 2 倍，每条轨道的运算与逐像素版本完全相同，结果逐位一致。轨道状态完全重复时提前判定为不逃逸。
   内部像素不会逃逸，若没有捷径，就会把整个迭代预算跑满。轨道接近此前的近零点后，用后续一个候选周期验证一个圆盘：按 `|f(w) − f(z)| ≤ r(2|z| + r)` 并计入每一步的舍入误差界，同时尝试四种初始半径，若 P 步后圆盘的像落回圆盘内，则 `f^P` 把它映入自身，轨道永不逃逸，像素即判定为内部。这是区间式的包含证明，不是近似阈值：它只会提前给出本来就会到达的“未逃逸”结论，逃逸像素的结果不受影响。尝试次数和步数都有上限，不会让单个像素的工作量超过一倍；超深层的扩展指数路径用以 2 为底的对数跟踪半径。
   有些内部区域的轨道收敛极慢：例如放大约 4.17×10^13 倍处、紧邻一个周期 211 迷你集的周期 844 分支，轨道每绕周期一圈只向周期点靠近约 12%，要 3.5 万到 14 万次迭代才出现足够接近的回归，大块黑色区域因此每个像素都要白跑十几万步。深层扰动路径因此在较粗略的回归（与近零点的距离在 |base| 的一半以内）时，先以该回归间隔 P 为周期，用牛顿法直接求解 `f^P(w) = w` 的周期点（每轮 P 步并同时计算导数，二次收敛），再在周期点周围用同样带舍入误差界的四种半径圆盘验证 `f^P` 把圆盘映入自身。由 Schwarz 引理，这说明存在吸引周期；而 `z² + c` 的吸引周期必然吸引唯一的临界点 0（Fatou），所以 0 的轨道有界、像素在集合内部，无需等轨道自己收敛过去。验证仍是严格的包含证明，参考轨道本身的舍入只在起点、终点和换参考点时进入总值，已分别计入。逃逸轨道也会经过排斥周期附近：牛顿迭代大致收敛后 |λ| ≥ 1 即放弃，第 k 次失败后等待 4P·2^k 步再试。在 163840 次迭代的预算下，上例渲染快约 4–7 倍、未定像素从约 16% 降到约 1%，约 1.83×10^12 倍的相邻视图快约 2–5 倍；纯外部的深层画面因失败尝试慢约 1–10%。浅层直接迭代与 10^270 倍以上的扩展指数路径仍只用前一种证明。
   相邻的内部像素属于同一个分支：周期相同，周期点随 c 连续移动。因此一个像素一旦由吸引周期证明为内部，下一个像素先以它的周期点为初值做同样的牛顿迭代与圆盘验证（至多 4 圈），成功即判定为内部，完全不必迭代自己的轨道；失败则照常迭代。证明对任何初值都成立，失败也不改变后续计算，所以每个像素的结果与采样顺序无关（测试以正反两种顺序比对）。大块黑色区域的整帧因此再快约 2–2.7 倍。
   深层在 Worker 中计算一条高精度参考轨道，像素通过扰动递推 `δz′ = (2Z + δz)·δz + δc` 复用它：与展开的 `2Zδz + δz² + δc` 相比少两次乘法，依赖链也更短，单步快约 1.36 倍；舍入误差不超过 `2^-53` 的若干倍乘以 `|2Z + δz||δz| ≤ 2|Z||δz| + |δz|²`，仍在内部证明所用的误差界之内，与 BigInt 对照的精度不变。参考轨道可在允许的范围内跨平移、缩放复用；参考点距视图中心超过 2^24 个 CSS 像素时会重新计算，避免缩小后再偏离中心深入放大时，像素差异被浮点精度吞没。
   高精度轨道只由 0 号 Worker 计算一次；每次迭代复用新值的平方同时完成逃逸判断和下一步，只需 3 次大整数乘法（原为 5 次），定点转浮点时先移位到约 64 位再求位长，不再把数千位的值转成二进制字符串，结果逐位相同，极深层的参考轨道快约 2.3 倍。轨道以紧凑的类型数组经主线程转发给其余 Worker，各自据此构建 BLA 表，结果与本地计算逐位一致。正在计算的轨道若仍被新请求需要会继续进行，不会因连续缩放反复重启。
3. 极深层的扰动使用独立的二进制指数，避免在约 `10^-308` 处下溢。满足保守误差半径时，BLA（双变量线性近似）跳过连续迭代；单步略去 `|δ|²` 的条件为 `|δ| < 2^-36 |2Z|`，等效于把采样点移动约 10^-8 像素，远小于边界附近精确逃逸次数在 10^-3 像素内本身的变化，跳过的迭代比 2^-42 多至数倍。普通深度的 BLA 表以每层一个 `Float64Array` 存储，内存约为对象形式的四分之一；每个位置先用第 0 层半径快速排除（更长的块半径不会更大），省去大多数查表；抵消阈值按轨道位置预先计算，参考值和 `|δ|²` 跨步复用，内部证明的跟踪先用保守的远离阈值排除，单步扰动的结果逐位不变。检测到严重抵消时回退到该像素的 BigInt 直接迭代；需要时重新对齐参考轨道。
   普通指数范围内的扰动使用平方模检查逃逸、抵消和 BLA 半径，避免在每一步重复调用模长和对数运算；平方可能下溢时回到稳定的模长比较，极深层仍使用扩展指数路径。
   绝大多数迭代是既不能用 BLA、也不需要任何记账的普通单步（典型视图中占 80–99%）。它们走一条精简的内循环，只做单步、导数和必要的检查；BLA 可能适用、逃逸、抵消、极小 |z|、周期跟踪真正需要处理（新的最小值、近回归，或此刻可以尝试牛顿证明）以及重置时，才交给通用代码。两条路径的运算与判断完全相同，结果逐位一致，深层像素快约 1.4–1.5 倍。也评估过两种更激进的做法：把 BLA 阈值放宽到 `2^-32`～`2^-24` 能少执行一半步数，但 `2^-28` 起就有像素超出精确值自身的变化范围，`2^-32` 在含大块内部的视图中反而更慢；仿照浅层交错推进两个扰动像素虽然逐位一致，但在 V8 中状态交接和寄存器压力的开销超过了收益。两者都未采用。
4. 主线程用 `requestAnimationFrame` 变换已有图像，立即响应手势；Worker 按需创建并复用，最多 8 个，通常为页面保留一个逻辑核心。根据待补算像素数、缩放深度和参考轨道的估算内存选择活动线程数，小区域会减少线程，极长参考轨道也会限制并发。先输出低分辨率预览，再按 8、4、2、1 像素步长补全细节。每一步最终都会到达实际画布分辨率。
   单独一次变化（一格滚轮、拖拽开始）立即开始渲染，不再固定等待 120 ms；连续变化中，上一轮显示出粗阶段且已过 180 ms 时重新开始，否则在最后一次变化后 60 ms 渲染。
   每个 Worker 在四个阶段中负责固定的空间分块。粗阶段在每个块的左上像素中心采样，因此每个粗采样都恰好是一个最终像素；更细的阶段直接沿用这四分之一的结果而不重算。最终图像与逐像素计算完全相同，总计算量减少约 25%。粗采样以采样像素为中心绘制（相邻分块的绘制范围恰好拼接，区域边缘由最后一列/行补齐），各阶段预览与最终图像的位置偏差不超过半个物理像素，细化时画面不会来回移动。
   缩放后新渲染的预览是旧图像的投影：放大 F 倍时，已完成到步长 s 的旧图相当于间距 F·s 的采样。比这更粗的阶段仍会计算（统计用于迭代预算），但不再覆盖这块更清晰的预览，否则颗粒会先变大再变小，看起来在清晰与模糊之间来回切换；最终阶段总会绘制。
   浅层每秒可完成上万个分块。Worker 约每 16 ms 批量发送一次，主线程把分块写入 CPU 暂存缓冲，每帧只向画布上传一次，避免大量小块上传阻塞手势和绘制。分块尚未被更细结果占用时整块认领，粗块按行展开后用 `copyWithin` 复制相同的行，主线程处理一次全图约 33 ms（原约 55 ms）。
   同倍率平移会复用重叠区域已完成的高清像素，只计算新露出的区域及尚未完成的部分。像素与完成状态一起按物理像素移动，避免反复插值造成模糊；不足一物理像素的位移保留在高精度视图坐标中累积，显示与坐标之间最多相差半个物理像素。缩放、窗口尺寸或屏幕像素密度变化，以及平移超过缓存范围时，重新计算全图。缓存限于当前画布，不会随探索距离无限增长。
5. 新请求会协作取消旧计算：Worker 每计算约 8 ms 让出一次以处理新消息，用自发的 `MessageChannel` 消息而非 `setTimeout(0)`（后者嵌套后被浏览器限制为至少 4 ms，会让 Worker 空等约三分之一的时间）；结果携带任务编号，旧结果不能覆盖新视口。分块质量记录阻止迟到的低分辨率结果覆盖已完成的高分辨率像素。
6. 迭代预算随深度增长，并按实际情况自适应：粗阶段有超过 1% 的采样在预算内既未逃逸也未被证明为内部时，预算提高到 4 倍并重新绘制（颜色只取决于逃逸次数，已逃逸的像素不变）。提高不再明显减少未定像素时停止，上限为深度公式的 64 倍（2^16 到 2^20 之间）；学到的预算在附近继续沿用，缩小 8 个二进制量级以上或按 Home 后恢复公式。例如海马谷约 10^15 倍处，按公式的 2560 次迭代整幅画面都是黑色，实际像素需要数千到数万次迭代。
   源码没有固定的放大倍数上限，但真实计算仍受 CPU、内存、迭代预算与数值误差影响；不能保证任意区域、任意深度都实时完成高清重绘。黑色表示已被证明不会逃逸，或在当前（自适应）预算内未逃逸；后者并非严格的集合归属证明。极深缩放时，先显示可即时操作的缓存画面，再渐进生成新细节。

配色复刻 [`Mandelbrot_sequence_new.gif`](https://commons.wikimedia.org/wiki/File:Mandelbrot_sequence_new.gif)，由动画全部 475 帧反推得到：

- **视图**：每帧都以海马谷目标点为中心，按每帧 1.1495 倍等比放大（共约 2^95 ≈ 4×10^28 倍）。拟合时不依赖任何配色：按算出的逃逸次数给像素排序，相邻像素颜色变化最小的视图即为该帧视图，各帧残差不超过 0.008 个二进制量级。
- **映射**：只取没有混色的平坦像素（其中心与四个亚像素角的逃逸次数相差不超过 2）配对颜色与逃逸次数，共约 300 万个样本。各帧在同一逃逸次数上的颜色相差 0–3 个色阶，说明原动画的颜色只是逃逸次数 n 的函数：渐变位置为 `frac(√(n + 4) / 32)`，即 √(n + 4) 每增加 32 走完一圈（n < 1020、< 4092、< 9212 …），后几圈与第一圈的颜色平均相差约 1 个色阶。
- **渐变**：正是生成器 [`MandelAnimator.java`](https://github.com/josch/mandelbrot_zomb/blob/master/src/deepZoom/MandelAnimator.java) 中的 10 个黄金渐变色（从深蓝紫、宝蓝、浅青、近白到金黄、橙、赭红、暗紫），均匀分布在一圈的 0、0.1 … 0.9 处，每个色标与实测相差不超过 1.7 个色阶；色标之间用周期 Hermite 样条连接，斜率按各帧拟合。与实测的 512 段渐变相比平均相差 1.7 个色阶、最大 5.8，接近 GIF 自身的量化误差；逐帧对比各深度平均相差 1.6–2.6 个色阶。
- **第一圈之后改为对数节奏**：第一圈（n < 1020，从深蓝紫、宝蓝、浅青、近白到金黄、橙、赭红、暗紫）与动画完全一致。动画之后的每一圈随 √n 越拉越长；在许多位置，逃逸次数随放大增长得很慢，整个画面乃至很多个放大量级都落在一圈中的一小段里，几乎只剩一种颜色（动画自己的深层帧也是如此）。因此第一圈之后，变化速率在 n = 1020–1500 之间平滑过渡（速率连续）到对数节奏：n + 4 每增大 e 倍走 4 圈，即逃逸次数每增加约 28% 走完一圈。逃逸次数相差约 10% 的画面在任何深度都能看到约 0.4 圈的颜色，放大时随着逃逸次数增长，各种颜色依次循环出现。配色仍只取决于逃逸次数，同一个点放大前后颜色不变，不需要任何手动调整。代价是动画第一圈之后各帧的主色调与原动画不同，但它们不再接近单色。
- **后续各圈更快地经过暗色段**：渐变中从赭红（0.8）经暗紫、深蓝紫到宝蓝（1.1）约四分之一都很暗（亮度低于约 40），深层画面的逃逸次数若正好落在这一段，整幅画面几乎全黑。因此从第二圈起，这一段以 3 倍速度经过（边缘按余弦平滑），在每圈中只占约十分之一，其余颜色相应分到更多；它仍作为赭红与蓝色之间的暗色点缀出现。第一圈保持原样，两者在深蓝紫处无缝衔接。例如放大约 1.37×10^107 倍的一个视图，平均亮度从 23 提高到 54（满分 255），由近乎黑红变为橙红配蓝色结构。
- **距离估计（DE）勾勒边界，保证对比度**：任何固定的“逃逸次数 → 颜色”映射，都会让某些画面的逃逸次数正好落在渐变中对比度很低的一段（浅青—近白—淡黄，或暗紫），细丝几乎融进背景。例如放大约 1.18×10^119 倍的一个视图，逃逸次数集中在 7578–7891，平坦着色的平均亮度达 241，几乎一片白。因此像许多深度缩放渲染器一样，迭代时同时计算导数 z' = dz/dc，在逃逸处得到每个像素到集合边界的距离估计 |z|·ln|z| / |z'|（与真实距离相差不超过约 2 倍），按屏幕物理像素计量：距边界半个像素以内的像素按距离的平方根逐渐压暗，紧贴边界处最多压暗 65%，所有通道等比例缩放，色相不变。细丝因此有清晰、平滑的轮廓，背景保持原色；距离来自每个像素自身的导数，不受相邻像素噪声影响，在任何深度、任何渲染阶段看起来都一样。色相仍只取决于逃逸次数，同一个点放大前后色相不变。第一圈（动画自身的配色）不加轮廓，第二圈内逐渐生效，初始画面与动画完全一致。
  导数以“每像素”为单位跟踪（z'_{n+1} = 2 z_n z'_n + 像素尺寸），在 10^270 倍以内始终处于双精度范围；更深的扩展指数路径单独记录 z' 的指数。BLA 跳步对导数同样是线性映射：z' ← A z' + B·像素尺寸。实测深层视图慢约 3–7%，扩展指数路径约 9%；浅层每次迭代本身很便宜，多出的导数运算约占 25%。
- 集合内部保持黑色。颜色只依赖逃逸次数和以物理像素计的边界距离，不随平移或迭代预算变化，已有像素缓存仍可复用。着色查 16384 段的打包 RGBA 表，每个像素一次查表。原 GIF 还使用多重采样抗锯齿，实时渲染没有增加采样数量，所以细丝处的颜色会比 GIF 更锐利。

配色位于 `src/palette.ts`，迭代预算和扰动算法位于 `src/fractal.ts`，指数扩展运算位于 `src/extended.ts`，手势和渲染调度位于 `src/main.ts`，页面样式位于 `src/style.css`。

算法依据：[Claude Heiland-Allen 的 Deep Zoom](https://mathr.co.uk/web/deep-zoom.html) 及 [Deep zoom theory and practice](https://mathr.co.uk/blog/2021-05-14_deep_zoom_theory_and_practice.html)。本项目为 TypeScript 实现，没有引入分形运行时依赖。

## 验证

使用 Node.js 22.18+（建议 24+）执行：

```sh
npm test
npm run build
```

测试覆盖鼠标锚点、画布外中心缩放、连续 3000 次缩放、深层拖拽、双指缩放和平移、触点取消、任务取消、渐进像素覆盖及乱序结果保护。数值测试用额外增加 64 位精度的直接 BigInt 迭代作对照，覆盖非实轴复杂边界和每像素 `2^-2000`（约 `10^-602`）的尺度；混沌边界区域按 10^-3 像素位移内的精确值变化范围比较。另有测试检查三路交错与逐像素结果逐位一致、内部证明在 4 倍 BigInt 预算下无一逃逸、超深层迷你集内部被快速证明、收敛极慢的内部区域由吸引周期证明（且边界两侧的证明在 4 倍 BigInt 预算下无一逃逸）、距离估计与高精度导数一致、粗采样复用后的深层图像与逐像素采样相同，以及预算自适应的提高、停止与遗忘；这验证了这些测试点，不代表对所有深度和边界的数学正确性证明。

## 性能基准

```sh
npm run bench
npm run bench:workers
# 可单独指定线程数（1–8）
npm run bench:workers -- 2 4 8
```

`bench` 对固定的五个视图采样 160×100 个像素，预热后报告三轮中位数、参考轨道准备耗时和像素校验和；可传入另一份 `src` 目录比较计算实现。`bench:workers` 使用实际 Worker、384×240 像素和完整渐进过程，包含消息传输，但不包含浏览器绘制。

2026-11-06 本机 Apple M1 Max 上，以 8 个 Worker 渲染 1280×800 整帧（含全部阶段与共享参考轨道）的一次对比，单步快速路径、`(2Z + δz)·δz` 与相邻周期提示合计：倍率 `1.50×10^47` 从约 0.80 s 降至 0.44 s，`1.37×10^107` 从 2.98 s 降至 1.80 s，海马谷 `10^15`（预算 10240）从 11.6 s 降至 8.6 s，含大块内部的 `4.17×10^13`（预算 40960）从 30.2 s 降至 11.0 s；测试时机器负载较高，绝对值偏大。更早的一次对比：深层样例（倍率 `1.50×10^47`）单线程采样从约 421ms 降至 82ms，海马谷样例从约 2155ms 降至 411ms；优化后的深层样例从 4 Worker 的约 197ms 降至 8 Worker 的约 113ms。前后采样校验和相同。结果受设备、位置和负载影响，扩展指数路径的收益较小，这些数值不代表所有视图的整页渲染速度。
